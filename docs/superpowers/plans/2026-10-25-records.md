# Records et progression Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Records par exercice (charge max, 1RM estimé) célébrés pendant et après la séance, courbe de progression dans la fiche, page « Mes records ».

**Architecture :**
- Calcul pur `src/domain/records.ts`.
- `src/data/records.ts` : lecture de l'historique local (séances terminées ou en cours, non allégées) et appels au calcul.
- Écrans : `ExerciseCard` (mention + vibration), bandeau de fin (`SessionPage`), `ProgressChart` + section Records dans `ExerciseSheet`, page `RecordsPage` (`/records`), lien dans le Profil.

**Tech Stack:** React 18, TypeScript, Dexie, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-25-records-design.md`

## Global Constraints

- Epley : `reps === 1 ? charge : charge × (1 + reps / 30)`, arrondi à 0,5 kg.
- Séries prises en compte : validées, `COUNTING_KINDS`, charge > 0, reps > 0, séance non allégée.
- Record = strictement mieux ; la première séance d'un exercice n'en produit aucun.
- Libellés : « 🏆 Record ! », « Charge max », « 1RM estimé », « Records », « 3 mois », « 1 an », « Tout », « Fais encore une séance pour voir ta courbe », « 🏆 Mes records », « Termine une séance pour voir tes records. ».
- Aucune donnée serveur, aucun partage, pas d'XP.

## Review Focus

- Un exercice présent deux fois dans la même séance : les séries sont prises dans l'ordre des positions.
- Unités en livres : affichage converti, calcul toujours en kg.
- Séance allégée en cours : aucune mention de record.
- Modifier la charge d'une série déjà validée : la mention se met à jour.
- Historique long : la page « Mes records » reste rapide (un seul passage sur les séries).
